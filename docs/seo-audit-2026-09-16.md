# Qala Labs — SEO Audit

**Date:** 2026-09-16
**Scope:** Full site (qalalabs.com), technical + on-page + content layers
**Health Score:** **51.5 / 100 (Grade D)** — ecommerce-weighted, computed from 26 checks (11 pass / 5 warn / 10 fail)
**Access used:** Live site (curl, multiple user-agents), full source repo, `WebSearch` for indexation spot-check. No Google Search Console, GA4, or PageSpeed Insights access was available for this pass.

---

## Executive Summary

- **The site's entire SEO investment isn't reaching search engines.** The codebase has a complete SSR pipeline (`server.js` + `entry-server.tsx`) purpose-built to serve crawlers real HTML — but production is served from Hostinger's static CDN, which never runs it. Every URL, including the homepage, blog posts, and case studies, returns the same bare, empty HTML shell to Googlebot, Bingbot, and even a plain `curl` request: 0 words, 0 H1, identical `<title>` everywhere.
- This single infrastructure gap cascades into nearly every other finding below: duplicate titles, 0-word "thin content," and structured data (JSON‑LD) that's written correctly in code but never appears in the HTML crawlers actually receive.
- **A `site:qalalabs.com` search returns only the homepage** — of the ~30 public pages listed in the sitemap, effectively none appear to be indexed individually. This corroborates the SSR finding with real-world evidence, not just a theoretical risk.
- **Ironic self-inflicted wound:** the site sells AI Search Visibility / AEO / GEO / Enterprise AI Automation services, but AI answer-engine crawlers (ChatGPT, Perplexity, Google AI Overviews) — which largely don't execute JavaScript — see the same empty shell as everyone else. The product being sold isn't being practiced on the site selling it.
- **Social sharing is broken sitewide**: the default Open Graph image is an SVG (`/og.svg`); Facebook, LinkedIn, X/Twitter, and iMessage do not render SVG for `og:image`, so every shared link shows a blank/broken preview. The `og.jpg` fallback that exists is a blank 1×1px placeholder, not a real fallback image.
- **Quick wins once the SSR gap is fixed**: several page titles exceed the ~60-char SERP display limit (Enterprise AI Automation, Industries, Creator Collective, Agency Network, Portfolio, Case Studies, Career), and a handful of pages (Privacy, Terms, all dynamic Portfolio detail pages) fall back to the sitewide default meta description, creating duplicate descriptions across an unknown number of DB-driven URLs.

**Fix priority:** everything else on this list is secondary until the SSR/static-hosting mismatch is resolved. Shipping on-page copy polish onto a site crawlers can't see is wasted effort.

## Technical SEO Findings

### 1. Crawlers receive an empty static shell, not the rendered page
- **Impact:** Critical
- **Evidence:** `curl https://qalalabs.com/` and `curl -A "Googlebot/2.1 ..." https://qalalabs.com/` both return the identical 3,890-byte static `index.html` with the `<!--app-head-->`/`<!--app-html-->` placeholders never replaced. Response headers show `Server: hcdn`, `platform: hostinger` — the request never reaches the Node/Express server that contains the SSR logic in `server.js`/`src/entry-server.tsx`. `seo_checker.py` against the live homepage measured **0 H1s, 0 words, 0 links**.
- **Fix:** Deploy the existing SSR build (`npm run build && npm start`) behind the domain instead of (or in front of) the current static Hostinger hosting — e.g., point the domain at the Node server, or move to a host that runs it (Vercel/Render/a VPS via reverse proxy), keeping Hostinger only for static asset/CDN duties if desired. This is a deployment/infra change, not a code change — the SSR code already exists and works per the repo's own `SSR_AND_META_TAGS_TECHNICAL_GUIDE.md`.
- **Priority:** 1 (blocking)

### 2. Every URL serves an identical `<title>` to non-JS clients
- **Impact:** Critical
- **Evidence:** `/` and `/blog/why-bnpl-core-payment-strategy-india` both returned `<title>Performance Marketing Agency for DTC Brands | Qala Labs</title>` via curl (default UA, Googlebot UA, and `facebookexternalhit` UA).
- **Fix:** Direct consequence of Finding #1 — resolves automatically once SSR is live, since `SEO.tsx` already sets per-page titles via Helmet correctly.
- **Priority:** 1 (blocking)

### 3. No canonical tag in raw HTML
- **Impact:** High
- **Evidence:** `grep canonical index.html` returns nothing; `<link rel="canonical">` is only added by `SEO.tsx` via client-side Helmet.
- **Fix:** Same root cause as #1; resolves once SSR is deployed. Canonical logic itself (`src/components/layout/SEO.tsx:32`) is correct.
- **Priority:** 1 (blocking)

### 4. `site:qalalabs.com` shows only the homepage indexed
- **Impact:** High
- **Evidence:** A live web search for `site:qalalabs.com` returned only `https://qalalabs.com/` — none of the ~30 sitemap URLs (services, case studies, portfolio, blog) appeared.
- **Fix:** Once SSR is fixed, submit the sitemap in Google Search Console and request indexing/inspection on priority URLs to accelerate recovery. Recommend setting up GSC monitoring going forward (not currently connected — no access was available for this audit).
- **Priority:** 1 (follow-on to #1)

### 5. Protected routes return 200 with no `X-Robots-Tag`
- **Impact:** Medium
- **Evidence:** `curl -I https://qalalabs.com/admin` → `HTTP/1.1 200 OK`, no `X-Robots-Tag` header, despite `server.js:203` explicitly setting `X-Robots-Tag: noindex, nofollow` for admin/login routes. `robots.txt` does correctly `Disallow: /admin`, `/login`, `/dashboard`, etc., which prevents crawling but not de-indexing of anything already indexed via external links.
- **Fix:** Same deployment gap as #1 — this header logic exists in code but isn't running in production.
- **Priority:** 2

### 6. Sitemap & robots.txt are otherwise solid
- **Impact:** N/A (pass)
- **Evidence:** `robots.txt` correctly allows crawling, references the sitemap, sets sensible crawl-delays, and blocks known aggressive scrapers (AhrefsBot, SemrushBot, MJ12bot, DotBot) — worth noting this also blocks *your own* ability to audit backlinks with those tools if you rely on them elsewhere. `sitemap.xml` covers all 26 public static/pseudo-static routes with reasonable `priority`/`changefreq` values.
- **Note:** `lastmod` dates are all hardcoded to `2026-06-25` — the sitemap isn't regenerated on content changes. Low priority, but worth automating once dynamic (DB-driven) case studies/blog posts/portfolio items scale up, since none of those individual dynamic slugs are in the static sitemap at all (only the hardcoded case-study/portfolio pages are listed; CMS-driven ones from Supabase aren't).
- **Priority:** 3

## On-Page SEO Findings

### 7. Several titles exceed the SERP display limit
- **Impact:** Medium
- **Evidence:** Measured against the ~50–60 char / ~600px guideline:
  - "Enterprise AI Automation Agency India | AI Agents & Workflow Automation | Qala Labs" (~85 chars)
  - "Industry-Specific Marketing & AI Solutions | Real Estate, SaaS, D2C, B2B | Qala Labs" (~86 chars)
  - "Creator Collective | UGC & Influencer Marketing for DTC Brands India | Qala Labs" (~82 chars)
  - "Agency Partner Network | Collaborate with a DTC Growth Agency India | Qala Labs" (~81 chars)
  - "Creative Portfolio | UGC, Influencer & Ecommerce Marketing Work | Qala Labs" (~76 chars)
  - "DTC Ecommerce Case Studies India | Proven Revenue Growth | Qala Labs" (~70 chars)
  - "Careers at Qala Labs | Join a DTC Performance Marketing Agency India" (~70 chars)
- **Fix:** Trim each to lead with the primary keyword phrase and drop to ≤60 chars including the " | Qala Labs" suffix. Example: "Enterprise AI Automation Agency | Qala Labs" (44 chars) with the "AI Agents & Workflow Automation" phrase moved into the meta description instead.
- **Priority:** 3 (quick win, but only matters once #1 is fixed)

### 8. Duplicate/missing meta descriptions on specific templates
- **Impact:** Medium
- **Evidence:** `Privacy.tsx` and `Terms.tsx` call `<SEO title="..." />` with no `description` prop, falling back to the sitewide default ("India's full-service AI growth agency…"). `PortfolioDetail.tsx` (the dynamic `/portfolio/:slug` template used for every Supabase-driven portfolio project not covered by a dedicated page component) also never passes a `description` — meaning every such project shares the identical default description.
- **Fix:** Add a real 1–2 sentence description to Privacy/Terms (even generic legal-page copy is better than the marketing default). Pull `project.description` from Supabase into the `<SEO description={...}>` prop in `PortfolioDetail.tsx`, mirroring what `CaseStudyDetail.tsx` and `BlogDetail.tsx` already do correctly.
- **Priority:** 2

### 9. Sitewide default meta description is under the optimal range
- **Impact:** Low
- **Evidence:** "Performance marketing & AI automation agency for DTC brands in India. We scale revenue, lower CAC, and build predictable growth systems." = 136 chars (`seo_checker.py` flags it as "too short" vs. the 150–160 target).
- **Fix:** Extend by ~15–20 characters to use the available SERP snippet space more fully, e.g. append a proof point ("...predictable growth systems — trusted by 40+ DTC brands scaling past ₹1Cr/mo.").
- **Priority:** 4

### 10. H1s and image alt text are fine in source — the problem is delivery, not authoring
- **Impact:** N/A (pass, noted for clarity)
- **Evidence:** Every marketing page component defines a distinct, on-topic H1 (confirmed across all ~30 pages in the companion content inventory). Spot-checked image components (`ClientLogos.tsx`, `AmazonAdsPortfolio.tsx`, `Team.tsx`, etc.) all have real `alt` text. The `seo_checker.py` result flagging "0 H1" and "1 image missing alt" reflects the empty SSR-less shell, not the authored React code.
- **Fix:** None needed at the code level; this resolves once #1 is fixed. Worth re-running `seo_checker.py` against the live URLs after the SSR fix ships, to confirm delivery matches source.
- **Priority:** N/A

## Content Findings

### 11. Structured data (JSON-LD) is well-built but invisible to crawlers
- **Impact:** Critical
- **Evidence:** `src/lib/seo.ts` implements Organization/WebSite schema (always injected), plus `generateCaseStudySchema`, `generateBlogSchema`, `generatePortfolioSchema`, `generateServiceSchema`, `generateFAQSchema`, and `generateBreadcrumbSchema` — a genuinely thorough structured-data layer, correctly wired into the relevant detail pages via the `jsonLd` prop on `<SEO>`. None of it reaches Google or Bing today because it's rendered into `<script type="application/ld+json">` tags by Helmet at React-render time, and that render never happens server-side in production (same root cause as #1).
- **Fix:** Resolves once SSR is deployed. Recommend re-validating with Google's Rich Results Test on a case study, blog post, and service page after the fix ships.
- **Priority:** 1 (follow-on to #1)

### 12. AI-answer-engine readiness undercut by the same gap — and it's the product being sold
- **Impact:** High (strategic/brand risk, not just technical)
- **Evidence:** The site has dedicated `/ai-search-visibility` and `/enterprise-ai-automation` pages pitching AEO/GEO expertise, complete with FAQ schema (`generateFAQSchema`) wired up correctly. But ChatGPT, Perplexity, and Google AI Overview crawlers largely don't execute JavaScript, so they see the same 0-word shell as every other bot.
- **Fix:** Same infra fix as #1, but call this out specifically to stakeholders — it's a credibility gap between what's sold and what's demonstrated, worth prioritizing ahead of a sales push on these service pages.
- **Priority:** 1

## Prioritized Action Plan

### Critical — fix before anything else matters
1. **Deploy the SSR server in production** instead of serving from static Hostinger hosting. This single fix resolves duplicate titles, 0-word "thin content," missing canonicals, and invisible structured data in one move.
2. **Verify the fix** with `curl -A "Googlebot" https://qalalabs.com/<page>` for a sample of pages, confirming per-page titles/descriptions/H1/JSON-LD all appear in the raw HTML.
3. **Re-run `seo_checker.py`** against the live homepage, a blog post, and a service page post-fix to confirm scores jump.

### High-impact
4. Fix the default social share image: replace `/og.svg` with a real PNG/JPG (1200×630) OG image; regenerate `og.jpg` (currently a blank 1×1px placeholder) as an actual branded image.
5. Submit the sitemap in Google Search Console and request re-indexing of key pages once SSR is live.
6. Add `description` to `PortfolioDetail.tsx`'s `<SEO>` call (pull from `project.description`), matching the pattern already used in `CaseStudyDetail.tsx`.

### Quick wins (easy, immediate benefit)
7. Trim the 7 over-length page titles listed in Finding #7 to ≤60 characters.
8. Add real meta descriptions to `Privacy.tsx` and `Terms.tsx`.
9. Extend the sitewide default meta description to 150–160 chars.

### Long-term recommendations
10. Automate `sitemap.xml` generation (including dynamic Supabase-driven blog/case-study/portfolio slugs, which aren't in the current static sitemap) instead of hand-maintaining hardcoded entries.
11. Get Google Search Console and PageSpeed Insights access connected for future audits — this pass had no visibility into real Core Web Vitals, crawl stats, or indexation history beyond a single `site:` search.
12. Once SSR is confirmed live, do a full internal-linking pass (not independently verified in this audit) and a breadcrumb-schema consistency check across all detail templates.
